### How the title's builder reaches us

- Our lists keep the put pointer and all limits at 0, so the title's inline
  packet code always falls back to the vtable (`crates/victory-gpu/src/list.rs:1-6`,
  test `every_inline_command_falls_back_to_the_table`, `list.rs:2467`).
- Dispatch: vtable[0xe] is `state::dispatch` (`list.rs:2349`, group counts);
  `DispatchX` (`list.rs:1553`) carries the thread-count flag. Both run
  `Draws::dispatch` (`crates/victory-gpu/src/draw.rs:3768`), which turns thread
  counts into groups (`draw.rs:3837-3850`). `ceil(count/32)` x 1 x 1 works on
  both paths.
- Upload memory: `allocate_upload` (`list.rs:1701`), 16-byte aligned or more,
  held until the list resets.

## Port order

1. NaN scrub back (from `77e13a974`), as a new module; plus the
   infinity-to-±65504 and integer-bits refinements (mandy) and the HDR clamp.
2. `rt_off_hashes.txt` and `rt_work_off_hashes.txt` back; `VIPRY.env` sets
   `VICTORY_RT_MISS=1` instead of the dead `VICTORY_BVH_MISS`.
3. kem wave-loop / LDS fixes (`2be0a9f68`), then `CS_ScreenProbes_ActivateRays`
   and `CS_RaytracingResolve` run behind a switch (kem, foxhound, mandy, klbf
   report magenta casts when they are skipped).
4. Builder-on fixes (check, xel, sley, Project-507): instance nodes all ones,
   recycled fault-page budget, `MEMORY_NEAR`, link-store drop, `BVH_COPY=skip`,
   `PORT_RT`, `AMBIENT_RT`.
